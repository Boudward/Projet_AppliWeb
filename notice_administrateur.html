Notice d'utilisation – Administrateur

Application « Travaux & maintenance » · version 2.5

Autres notices : Demandeurs · Responsables · Agents

1. Votre rôle

L'administrateur a tous les droits : il voit et modifie tous les tickets et interventions, gère les comptes, les listes de choix, l'annuaire des entreprises et lit les suggestions. Ces fonctions sont regroupées dans la console admin (bouton en haut de page ; le bouton Retour ramène aux tickets). Vous restez dans la console après chaque modification.

2. Gérer les comptes

Demandes de compte

Les personnes demandent un compte depuis la page de connexion (nom, prénom, société, fonction, e-mail, sans mot de passe). Dans le bloc Demandes de compte de la console, chaque demande indique l'état du compte :

  • Pas de compte : aucune invitation n'a été envoyée ;
  • Compte créé, jamais connecté : la personne a été invitée mais ne s'est pas encore connectée ;
  • Connecté (date) : le compte est actif et utilisé.

Procédure :

  1. Choisissez le rôle à attribuer puis cliquez sur Approuver (ou Refuser).
  2. Dans Supabase, ouvrez Authentication > Users > Add user > Send invitation, avec la même adresse e-mail que la demande. La personne reçoit un lien pour choisir son mot de passe. Le profil se remplit alors automatiquement avec ses informations et son rôle.
  3. Variante sans e-mail : Create new user avec un mot de passe provisoire (à communiquer vous-même). Approuvez toujours la demande avant de créer le compte.
  4. Quand la colonne indique « Connecté », vous pouvez Supprimer la demande.

À savoir : le service d'e-mail intégré de Supabase limite le nombre d'envois par heure. Pour un usage régulier, configurez un SMTP personnalisé (Authentication > SMTP Settings) et renseignez l'adresse de votre page dans Authentication > URL Configuration (Site URL).

Utilisateurs

Le bloc Utilisateurs permet de changer le rôle d'une personne et d'activer ou désactiver son compte. Les six rôles sont : Demandeur, Responsable bâtiments, Responsable exploitation, Agent bâtiment, Agent exploitation, Admin. La suppression définitive d'un utilisateur se fait dans Supabase (Authentication > Users).

3. Les listes et l'annuaire

  • Sites et zones/tribunes : ajout et suppression. Un élément utilisé par des tickets ne peut pas être supprimé.
  • Catégories et corps d'état : ajout et suppression de corps d'état pour Travaux/maintenance et Exploitation. Supprimer un corps d'état ne casse pas les tickets existants.
  • Annuaire des entreprises : cochez les catégories où le contact doit apparaître (Travaux/maintenance, Exploitation), choisissez le corps d'état (facultatif), puis saisissez l'entreprise, le chargé d'affaires, l'e-mail et le mobile (les espaces s'ajoutent automatiquement). Le lien modifier recharge un contact dans le formulaire ; Enregistrer les modifications valide, Annuler abandonne. Le lien supprimer retire le contact.

4. Suggestions des utilisateurs

Le bloc Suggestions des utilisateurs liste les idées envoyées avec le bouton ampoule : type, titre, détail, auteur, rôle et date. Vous pouvez les marquer comme traitées ou les supprimer.

5. Tester les rôles

Le sélecteur Voir en tant que simule l'affichage d'un rôle (demandeur, responsables, agents). C'est une simulation d'affichage : vous gardez vos droits d'administrateur. Pour un test fiable des restrictions, utilisez un compte réel par rôle. Le bouton ? ouvre la notice du rôle simulé.

6. Mettre à jour l'application

  1. Exécutez les scripts SQL dans Supabase (SQL Editor), dans l'ordre, une seule fois chacun : `schema.sql`, `migration_demandes_compte.sql`, `migration_v1_1.sql`, `migration_v1_2.sql`, `migration_v2.sql`, `migration_v2_1.sql` à `migration_v2_5.sql`.
  2. Remplacez `index.html` et les fichiers de notices sur GitHub (même dossier), puis rechargez la page avec Ctrl+F5.
  3. La version figure en bas de page, en texte de la couleur du fond : Ctrl+A la fait apparaître.
  4. `donnees_test_tickets.sql` crée des tickets fictifs « [TEST] » ; la dernière ligne du fichier, en commentaire, permet de les supprimer.

7. Sécurité

  • Seule la clé « publishable » de Supabase figure dans `index.html`. Ne mettez jamais la clé « secret » ou service_role dans ce fichier.
  • Les droits de chaque rôle sont appliqués par la base de données (règles RLS), pas seulement par l'écran.
  • L'historique horodaté des tickets (créations, statuts, modifications) est conservé pour de futures statistiques ; il n'est lisible que des responsables et de l'administrateur.

Aide et suggestions

En haut à droite de l'écran, le bouton ? ouvre cette notice et le bouton ampoule permet d'envoyer une idée, une amélioration ou un problème rencontré à l'administrateur : choisissez le type, donnez un titre, détaillez, puis Envoyer la suggestion.
